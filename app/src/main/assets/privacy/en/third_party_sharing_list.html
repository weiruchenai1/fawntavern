Third-Party Information Sharing List

Last updated: August 18, 2026
Effective date: August 18, 2026

  • The app transmits information to a relevant service only when you use a network feature or after consent when remote diagnostics and statistics are enabled.
  • The local libraries listed below implement app features. Merely including a library does not provide your data to that library's developers.
  • Third-party processing may change with versions, configuration, or service rules. The app does not include external links to these providers.

User-Configured AI, Search, TTS, and Image Services

  • Information involved: Input text, conversation context, images, files, search terms, text to synthesize, model and request parameters, API keys, request addresses, IP address, and network metadata.
  • Purpose: Complete AI, search, speech synthesis, and image requests you initiate.
  • Scenario: When you configure a service and send, search, synthesize, or load a remote image.
  • Third party: The relevant provider selected and configured by you.
  • Method: The app sends a network request. The provider determines retention and further processing.

Built-In Search Services

  • Information involved: Search terms, request address, IP address, request time, and network metadata.
  • Purpose: Retrieve and parse search results.
  • Scenario: When you enable web search and submit a search request.
  • Third party: Bing or DuckDuckGo, depending on your search configuration.
  • Method: The app uses OkHttp and Jsoup to request and parse results. Jsoup parses returned content locally.

Firebase Analytics

  • Information involved: App instance identifiers, device and system information, app version, build type, and app start events.
  • Purpose: Usage statistics and stability analysis.
  • Scenario: In configured release builds outside mainland China, after privacy consent and while remote diagnostics are enabled.
  • Third party: Google LLC.
  • Method: Transmitted by the Firebase Analytics SDK. Chat content is not included.

Firebase Crashlytics

  • Information involved: Crash stack traces, device and system information, app version, build type, runtime state, and diagnostic logs.
  • Purpose: Analyze crashes and diagnose stability issues.
  • Scenario: In configured release builds outside mainland China, after privacy consent and while remote diagnostics are enabled.
  • Third party: Google LLC.
  • Method: Processed by the Firebase Crashlytics SDK. Chat content is not intentionally uploaded.

Bugly CrashReport

  • Information involved: Crash stack traces, device identifiers, device and system information, app version, build type, runtime state, and privacy-related diagnostic information.
  • Purpose: Analyze crashes, device state, and runtime issues.
  • Scenario: In mainland China when a release build has a Bugly app ID configured, after privacy consent and while remote diagnostics are enabled.
  • Third party: Tencent Bugly.
  • Method: Processed by the Bugly SDK. Chat content is not intentionally uploaded.

Cloudflare Region Detection

  • Information involved: IP address, request time, network metadata, and the country or region code returned for the request.
  • Purpose: Select a regional remote diagnostics service and cache the region result.
  • Scenario: After privacy consent, while remote diagnostics are enabled, when the app needs to refresh region detection.
  • Third party: Cloudflare, Inc.
  • Method: The app retrieves region information through an HTTPS request.

OkHttp

  • Information involved: Request addresses, headers, request bodies, response status, and network metadata.
  • Purpose: Provide HTTP, SSE, search, update, and remote image communication.
  • Scenario: When the app or a plugin makes a network request.
  • Third party: Maintainers of the Square open-source project.
  • Method: OkHttp performs network communication locally. Data is sent to the request destination, not to OkHttp maintainers.

Coil

  • Information involved: Remote image or icon URLs, request status, and network metadata.
  • Purpose: Load avatars, character images, icons, and other remote images.
  • Scenario: When the interface needs to display a remote image.
  • Third party: Maintainers of the Coil open-source project.
  • Method: Coil calls OkHttp locally. Image requests go to the server identified by the URL, not to Coil maintainers.

Jsoup

  • Information involved: Web page HTML received locally and parsed results.
  • Purpose: Parse search results and message HTML locally.
  • Scenario: When a search returns a web page or chat content needs HTML parsing.
  • Third party: Maintainers of the Jsoup open-source project.
  • Method: Jsoup parses data locally and does not transmit it to its maintainers.

AndroidX Room / Paging

  • Information involved: Local chat database, conversation indexes, and paging state.
  • Purpose: Store, query, and display chat data locally.
  • Scenario: When the app reads or updates the local workspace.
  • Third party: Maintainers of the Google AndroidX open-source project.
  • Method: Processed only on the device, with no network transmission to maintainers.

QuickJS Kotlin

  • Information involved: Installed plugin scripts, manifests, configuration, and input passed to plugins.
  • Purpose: Run JavaScript plugins in an isolated local plugin process.
  • Scenario: When you install and enable a plugin or the app invokes it.
  • Third party: Maintainers of the QuickJS Kotlin open-source project.
  • Method: The runtime processes data locally. If a plugin makes its own network request, the relevant network service receives that request data.

GitHub Update Check

  • Information involved: Request IP address, request time, app-identifying User-Agent, and network metadata. The current version is compared locally.
  • Purpose: Check whether a newer app version is available.
  • Scenario: When you open the update check feature.
  • Third party: GitHub, Inc.
  • Method: The app retrieves version information over the network and does not upload chat content or API keys.

This list is not a complete statement of each provider's service. Before configuring or enabling a third-party service, evaluate its actual rules and decide whether to use it.
